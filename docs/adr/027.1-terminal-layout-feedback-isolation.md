# ADR-027.1: Terminal Layout Feedback Isolation

## Context

ADR-027 established who decides terminal geometry: the server owns the grid
(cols × rows, arbitrated across clients, sole writer of PTY `winsize`); the
client proposes and applies. That answered the *grid* domain. This addendum
answers the domain ADR-027 left implicit: the client-side **surface** domain —
how the pixels under that grid are measured, sized, and painted — after a
user-visible failure showed it had the same "no single owner" disease one
layer down.

### The incident

Opening a `GhosttyTerminal` inside a bordered, fixed-height modal made the
terminal's height grow without bound, with the browser reporting:

```
ResizeObserver loop completed with undelivered notifications.
```

### Root cause chain (three defects, one disease)

1. **Measurement arithmetic error.** `readHostContentBox()` derived the host
   "content box" as `getBoundingClientRect()` minus padding. But
   `getBoundingClientRect()` returns the **border box**. On a bordered host
   the measurement was border-width too large (2px for a 1px border).

2. **A structural feedback path.** The canvas was an **in-flow** child of the
   measured host. `canvasBox()` sizes the paint surface to fill the host
   (`max(gridCss, host)`), so the 2px-too-tall canvas pushed the host's
   border box 2px taller. The host's `ResizeObserver` fired, re-measured
   (border still included), grew the canvas again — divergence. The
   server-decided grid never changed during the runaway; this loop was
   entirely client-side, pixels only.

3. **Layout writes during observer delivery.** Even after (1) was fixed, the
   observer callback resized the canvas *synchronously, mid layout pass*.
   The browser reports the "undelivered notifications" warning for any
   layout mutation during delivery — even a converging one-shot change (a
   dialog animating open). Surfaced as a dev-overlay runtime error on every
   dialog reopen.

The disease common to all three: **the element we measure and the element we
mutate lived in the same layout circuit.** Fixing the arithmetic (defect 1)
made the loop converge but left the circuit closed — any future measurement
error (stale computed styles, engine rounding, a new CSS feature) would
re-open the runaway. A patch, not a fix.

## Decision 1: The canvas lives outside the measured layout flow

The terminal builds a **library-owned subtree** inside the consumer's host
(the xterm.js pattern — its `.xterm-screen` is equivalently isolated):

```
consumer host (never styled by us; sized by the consumer)
└── root div      ← ours: borderless, padding-free, 100%×100%, overflow:hidden,
    │               position:relative — THE measured element
    ├── canvas    ← position:absolute — OUT of the measured flow
    └── textarea  ← hidden IME input (absolute, as before)
```

- The **root** is what the `ResizeObserver` observes and what geometry
  measures. It has no border and no padding *by construction*, so the
  border-vs-content arithmetic that caused defect 1 has **no inputs left**.
- The **canvas** is absolutely positioned: it cannot influence the measured
  element's size, no matter how wrong its dimensions are. A mismeasured
  canvas is a one-frame cosmetic glitch instead of a divergent loop —
  "make illegal states unrepresentable," applied to layout.
- The root's `overflow: hidden` clips any overpaint at the host boundary, so
  a wrong canvas size can't visually escape the consumer's box either.
- Disposal removes the root subtree; the consumer's element is left exactly
  as found. The library **never styles the consumer's element** (an earlier
  draft set `position:relative`/`overflow:hidden` on the host directly —
  rejected as a boundary violation; owning a subtree is the version of that
  idea that respects the boundary).

**The invariant this ADR exists to record:** *the observer's subject must
never be layout-downstream of anything the terminal writes.*

## Decision 2: Measurement comes from the observer entry, not re-derivation

`ResizeObserverEntry.contentBoxSize` *is* the content box, computed by the
browser and delivered with the notification. The observer callback consumes
it directly; `readHostContentBox()` (now border-aware) survives only for the
single initial pre-observation read, plus an older-engine fallback.

Rationale: our manual `rect − padding − border` subtraction was a translation
layer re-implementing the browser's own domain language, and defect 1 was a
translation error. Deleting the translation deletes the bug class. This is
also how xterm.js's WebGL addon sizes its device-pixel buffers
(`DevicePixelObserver.ts`, `device-pixel-content-box`) — same principle, one
box-type up.

## Decision 3: One scheduling domain per pipeline phase

The reaction pipeline is now: **measure** (observer entry, cached) →
**propose** (pure function in `TerminalGeometry`) → **decide** (authority,
per ADR-027) → **apply** (canvas write, deferred one `requestAnimationFrame`,
coalescing multiple observations per frame).

The rAF deferral fixes defect 3: no layout writes occur during observer
delivery, so layout settles cleanly within each observation cycle. This
extends ADR-027's "one writer" discipline from the grid down to the pixels:
the renderer's rAF-scheduled apply is the only layout writer in the circuit.

## Decision 4: Defense-in-depth for the unknown regression

Should be dead code by construction, kept because it converts a catastrophic
failure mode into a bug report:

- **Divergence breaker:** ≥20 consecutive monotonic height-growth
  observations (the signature of a feedback loop; real user resizes settle)
  → suspend resize reactions, `console.error` with the inputs (host box,
  canvas style sizes), keep the terminal usable at its current size.
- **Static invariant (pre-existing, kept):** `canvasBox()` warns when the
  decided grid exceeds the measured host.
- **Unsized-host warning:** `open()` warns if the initial box is 0×0 —
  the terminal fills its host and does not invent a size (see Decision 5).

## Decision 5: The consumer sizes the host; the library never does

Fixing Decision 1 surfaced a masked collision: the React host
(`<GhosttyTerminal/>`'s div) set inline `width/height: 100%` by default.
Inline styles beat classes, so a consumer's `h-64` was being silently
overridden; before this ADR the in-flow canvas gave the host content height
and masked it — with the canvas out of flow, the host collapsed to 0 and the
terminal rendered blank.

The React host now sets only `display:block; position:relative` inline.
Sizing is the consumer's job through `className` or `style`, as shown by
fixed-height and flex-constrained hosts. The 0×0 warning from
Decision 4 catches the consumer who forgets. Same boundary principle as
Decision 1: cross-boundary style mutation is how this whole bug class starts.

### Related fix that rode along: default font stack

An early consumer hard-coded a Nerd Font stack in its terminal wrapper to
get eza/p10k icons rendering. Wrong layer for the same reason: glyph coverage
is a terminal-domain concern, not a consumer concern. The library now ships
`DEFAULT_FONT_FAMILY` (exported, overridable): local Nerd Fonts →
`ui-monospace`/Menlo/Consolas → `monospace`. Canvas `fillText` falls back per
glyph, so the stack costs nothing when absent; cell metrics are measured with
the same stack, so measurement and paint cannot disagree. Known limitation:
it relies on locally installed fonts — a machine with no Nerd Font still
shows tofu for PUA glyphs. The self-contained alternative (bundling a woff2,
~1MB, loaded via `FontFace` *before* metric measurement) is deliberately
deferred: real asset weight, and the initial consumers are developer workstations.

## Consequences

**Positive:**

- The resize feedback loop class is structurally unrepresentable, not merely
  numerically convergent — correctness no longer depends on measurement
  arithmetic being right.
- No layout writes during observer delivery; the browser warning (and the
  dev-overlay error it caused) is gone at the mechanism level.
- The library/consumer style boundary is now explicit and symmetric: we never
  style their element, they never need to style ours.
- Future regressions self-report with inputs attached instead of eating the
  page.

**Negative / accepted costs:**

- One more DOM element per terminal (the root div).
- Consumers MUST size the host; an unsized host is a warning + blank
  terminal rather than a content-sized guess. (Accepted: every real call
  site already sizes it, and the guess is what masked defects for weeks.)
- `contentBoxSize` requires a ResizeObserver level-2 engine (2020+
  browsers); the fallback re-derives via the fixed `readHostContentBox`.

## Re-evaluation triggers

- A consumer that cannot size its host (e.g. intrinsic-size embedding) →
  revisit Decision 5 with an explicit opt-in fill mode, never a default.
- Blurry rendering at fractional DPR → adopt `device-pixel-content-box`
  observation for the canvas buffer (xterm.js `DevicePixelObserver`
  pattern); the entry-consuming observer from Decision 2 makes this a small
  step.
- A non-dev-box consumer population appears → revisit bundling Symbols Nerd
  Font Mono via `FontFace` ahead of metric measurement.
